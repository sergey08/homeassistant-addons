# Nod 0.10.3 validation on Home Assistant

The candidate under test is Server 0.1.0-dev.35, Browser 0.1.0-dev.7 and Workspace 0.1.0-dev.7. The original dev.34 Server and dev.6 workers are the rollback set. Keep the three apps and their private options and data together. The first Home Assistant validation is on the disposable VMware instance. The Lenovo installation requires separate approval.

## Update rehearsal

1. Record the installed versions and app slugs from the VMware instance. Enable the test catalog only when its three image tags and anonymous pull digests have been verified. Use the original app slugs for an in-place update. A test catalog with a different repository prefix is suitable for a clean installation.
2. In the test installation, create a chat, memory note, saved login with synthetic credentials, a local model configuration, an MCP connector and a disabled schedule. Generate and download a document. Record what must still be available after the update.
3. Quiesce Nod, stop Server and wait for the PostgreSQL process to exit. Stop Browser and Workspace. Make a private partial backup covering all three apps and their configuration. Record its ID and verify all three entries. Retain the previous images and a recoverable VMware snapshot. Keep the partial backup and any optional HTTPS certificates private.
4. Check that Supervisor offers exactly the three versions in the published candidate. Upgrade the workers and Server as one maintenance operation. Keep the panel closed until the set matches and every component reports ready. If a worker cannot resolve the Server while it is stopped, start the updated Server and then start the workers and verify their authenticated channels. Test a second clean install from the integration separately.
5. Check the data and runtime below. Restart the VM, verify the same data and confirm a harmless schedule runs at the expected time. Disable the test schedule after the exercise.
6. Rehearse rollback in VMware. Stop all three apps and restore the matched pre-upgrade backup and previous images, or restore the pre-upgrade VMware snapshot. Start the previous set and repeat the data checks. Reusing the upgraded data volume with the old image is outside this rollback procedure.

## Runtime checks

| Area | Evidence to capture |
| --- | --- |
| Ingress | Open the original panel in LAN HTTP and HA HTTPS, desktop and mobile. Check login, chat streaming, Vault navigation, a retained attachment and a new download. Check rejection without an HA administrator session. |
| Models | Complete a real ChatGPT subscription sign-in and send one short message. Check the existing local model, Reload models, and recovery from a synthetic failed context with Restart chat. |
| Connectors | Read a harmless value from an authorized MCP connector and confirm one authorized external connector works. Use an HA HTTPS context for hosted sign-in. |
| Workers | Run a harmless task against a public test page, take a screenshot, create a document, and download it. Verify transport starts with protection enabled and automated checkpoints still pass. |
| Persistence | Check the original chat, memory, preference, Vault login, configured models, connector, schedule, options and document after upgrade, restart, and rollback. Computer use remains a status screen with no desktop control on HA. |

## Coordinated updates

The current integration installs and pairs the three apps. Its next update flow should show the full version set, ask for one explicit confirmation and verify a successful partial backup before applying sequential updates. Check the advertised and installed versions before and after each operation. Supervisor applies the current store version for each individual update. On an interruption, report the last completed operation and recover from the matched backup if resuming cannot reach the verified version set. Require an isolated rehearsal of both ordinary updates and interruption before offering the action to production users.

# Validación de Nod 0.10.3 en Home Assistant

La candidata de pruebas usa Server 0.1.0-dev.35, Browser 0.1.0-dev.7 y Workspace 0.1.0-dev.7. Server dev.34 y los dos workers dev.6 forman el conjunto de reversión. Conserva juntos las tres aplicaciones, sus opciones privadas y sus datos. La primera validación de Home Assistant se hace en la instancia desechable de VMware. La instalación del Lenovo requiere aprobación aparte.

## Ensayo de actualización

1. Anota las versiones instaladas y los identificadores de las apps en VMware. Habilita el catálogo de pruebas cuando se hayan verificado las tres etiquetas de imagen y sus digests en descargas anónimas. Usa los identificadores originales para actualizar una instalación existente. Un catálogo con otro prefijo permite ensayar una instalación limpia.
2. Crea en la instalación de pruebas una conversación, una nota de memoria, un inicio de sesión guardado con credenciales ficticias, un modelo local, un conector MCP y una tarea desactivada. Genera y descarga un documento. Anota los datos que deben reaparecer tras actualizar.
3. Deja que Nod termine el trabajo en curso, detén Server y espera a que se cierre PostgreSQL. Detén Browser y Workspace. Haz una copia parcial privada de las tres apps y su configuración. Anota el ID de la copia y verifica que incluye las tres. Conserva las imágenes anteriores y una instantánea recuperable de VMware. Mantén en privado la copia y los certificados HTTPS opcionales.
4. Comprueba que Supervisor ofrece las tres versiones exactas de la candidata publicada. Actualiza los workers y Server en la misma intervención. Espera a que coincidan las tres versiones y estén listos los componentes antes de abrir el panel. Si un worker necesita resolver Server durante el arranque, inicia el Server ya actualizado, luego los workers y verifica sus canales autenticados. Ensaya por separado una instalación limpia desde la integración.
5. Comprueba los datos y las funciones de la tabla. Reinicia VMware, verifica de nuevo los datos y confirma que una tarea inocua se ejecuta a la hora prevista. Desactiva la tarea de prueba al terminar.
6. Ensaya la reversión en VMware. Detén las tres apps y restaura la copia anterior junto con sus imágenes, o recupera la instantánea previa de VMware. Arranca el conjunto anterior y repite las comprobaciones de datos. La reversión utiliza los datos y las claves de dev.34 tomados antes de la migración.

## Comprobaciones funcionales

| Área | Evidencia |
| --- | --- |
| Ingress | Abre el panel en HTTP local y HTTPS de HA, en ordenador y móvil. Prueba autenticación, streaming, navegación de Vault, un adjunto anterior y una descarga nueva. Confirma que se rechaza el acceso sin sesión administradora de HA. |
| Modelos | Completa un inicio real con la suscripción de ChatGPT y envía un mensaje breve. Comprueba el modelo local, Reload models y la recuperación de un contexto fallido de prueba con Restart chat. |
| Conectores | Lee un dato inocuo de un MCP autorizado y prueba un conector externo autorizado. Usa HA por HTTPS para el inicio de sesión alojado. |
| Workers | Ejecuta una tarea inocua sobre una página pública de prueba, toma una captura, genera un documento y descárgalo. Comprueba que el transporte arranca con protección activa y registra los resultados de CI. |
| Persistencia | Verifica la conversación, memoria, preferencia, entrada de Vault, modelos, conector, tarea, opciones y documento tras actualizar, reiniciar y revertir. Computer use sigue mostrando el estado, sin acceso al escritorio de HA. |

## Actualizaciones coordinadas

La integración actual instala y empareja las tres apps. El próximo flujo debe mostrar las tres versiones, pedir confirmación una sola vez y verificar la copia parcial antes de actualizar en secuencia. Comprueba las versiones anunciadas e instaladas antes y después de cada operación. Supervisor aplica la versión vigente del catálogo por aplicación. Si se interrumpe el proceso, muestra la última operación completada y recupera la copia emparejada cuando no se pueda reanudar hasta el conjunto verificado. Ensaya la actualización normal y una interrupción en VMware antes de ofrecer la acción para producción.
