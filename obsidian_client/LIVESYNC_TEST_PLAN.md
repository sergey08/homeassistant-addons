# Real LiveSync fixture validation / Validación con datos reales de LiveSync

## English

Our existing `test_real_couchdb.py` writes *synthetic CouchDB documents*. It validates database roundtrips, **not** compatibility with documents generated by the Self-hosted LiveSync Obsidian plugin.

### Safe next milestone

1. Create a **new empty vault** in Obsidian Desktop, without copying personal notes.
2. Set up the Self-hosted LiveSync plugin against a **separate disposable CouchDB database** with a distinct name and dedicated least-privilege credentials. Never point the test vault to an existing production database.
3. Create only non-sensitive sample notes: plain Markdown, a note in a nested folder, a wiki link, a small attachment, and an edit from a second client.
4. Verify synchronization using Obsidian itself.
5. Capture a **sanitized representation of the document structure** for regression tests. Do not commit credentials, real database URLs, encryption keys, personal note contents, or full raw records.
6. Compare structures with our parser; explicitly mark encryption/compression/obfuscation variants as unsupported until covered with separate fixtures and tests.
7. Only after reliable reading, work on editing, optimistic concurrency (`_rev`), conflict reconciliation and recovery.

### Acceptance criteria
- Tests clearly distinguish synthetic test records from real LiveSync-generated records.
- Unsupported formats fail closed without corrupting any documents.
- Tests use an isolated database and do not modify a personal vault.
- The user-facing app remains independent from Obsidian MCP.

## Español

La prueba actual `test_real_couchdb.py` escribe *documentos CouchDB sintéticos*. Verifica lecturas y escrituras en la base de datos, pero **no** la compatibilidad con documentos generados por el complemento Self-hosted LiveSync de Obsidian.

### Próximo hito seguro

1. Crear una **bóveda vacía** nueva en Obsidian Desktop, sin copiar notas personales.
2. Configurar Self-hosted LiveSync con una **base CouchDB independiente y descartable** y credenciales específicas de mínimos privilegios. Nunca apuntar las pruebas a la base real.
3. Crear únicamente notas ficticias: Markdown simple, carpeta anidada, enlace wiki, adjunto pequeño y modificación desde un segundo cliente.
4. Comprobar desde Obsidian que sincroniza correctamente.
5. Obtener una **representación saneada de la estructura** para las pruebas. No publicar credenciales, URL reales, claves de cifrado, notas privadas ni documentos completos sin revisar.
6. Comparar esa estructura con nuestro lector y señalar expresamente las variantes cifradas, comprimidas u ofuscadas como no compatibles hasta probarlas.
7. Solo cuando la lectura sea fiable, desarrollar edición, control de revisiones `_rev`, conciliación de conflictos y recuperación.

### Criterios de aceptación
- Diferenciar claramente documentos sintéticos de los generados por LiveSync real.
- Rechazar formatos desconocidos sin corromper documentos.
- Usar una base aislada sin modificar la bóveda personal.
- Mantener el cliente completamente independiente de Obsidian MCP.
